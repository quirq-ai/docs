A project is one of your repos. A space holds projects, each at a ref (a
branch, tag or commit), so anyone who installs the space gets the same
checkouts. xo keeps both lists in your XO account; the clones are on your
machine.

## Add a project

```sh
xo create project https://github.com/juanfont/headscale   # cloned into ./headscale
xo create project notes                                    # no GitHub remote: ./notes, git init
xo projects                                                # your projects
```

A GitHub project is called by its repo's name, `headscale`, in every command.
When two of your projects share that name, such as a fork and its upstream,
call it by `OWNER/REPO`; its folder is then `./OWNER/REPO`.

A project made from a plain name can get its repo later:

```sh
xo connect notes --repo https://github.com/OWNER/REPO
```

It is called `REPO` from then on, and `./notes` gets that origin if it has
none and moves to `./REPO`.

## Put it in a space

```sh
xo connect headscale my-cc --ref main   # the project headscale in the space my-cc, at main
xo connect dev                          # a new space entry, with no XO Cloud space
xo connect old --id THE_ID              # an entry for an XO Cloud space you already have
xo spaces                               # your spaces, with their projects and refs
xo list                                 # your projects and your spaces together
```

xo works out which name is the project and which the space, so
`xo connect my-cc headscale` works too. For a space named like one of your
projects, say `space:NAME`; `project:` and `space:` work in front of any name.

### A project you have not added yet

```sh
xo connect https://github.com/OWNER/REPO my-cc   # adds the project, then puts it in my-cc
xo install space:my-cc                           # clones it into ./my-cc/REPO
```

`xo connect PROJECT SPACE` adds a project that is not in your projects yet,
as `xo create project` does but without making its folder, then puts it in
the space, and says so.

- Give the project as `OWNER/REPO` or a GitHub URL. A plain name becomes a
  project with no repo, which `xo connect NAME --repo URL` can give one later.
- Nothing is added when the space is missing. If the space then refuses the
  project (it is full, say), the project stays in your projects.
- A plain name close to one of your projects, most likely a typo, is refused
  with the name it is close to, since xo cannot delete a project. To add it
  anyway, say `project:NAME`.
- Put a new plain name first. `xo connect my-cc notes` is refused when `my-cc`
  is one of your spaces, since `notes` could be a space you have not made yet:
  say `xo connect project:notes space:my-cc`. `OWNER/REPO` and a URL work in
  either order.

<Callout type="info">
  If the first command above stops with `connect what?`, your xo is older than
  this: [update it](/docs/xo/install#update-or-remove).
</Callout>

## Install, update and sync

```sh
xo install space:dev    # ./dev/REPO for each project, at its ref
xo update space:dev     # push each branch under ./dev, then record the refs
xo sync space:dev       # rebase and push each branch, merge the space's refs, record
```

The same three work on one project: `xo install project:headscale` clones it
here (or fetches and fast-forwards it), `xo update project:headscale` pushes
its branch, and `xo sync project:headscale` runs `git pull --rebase`, then
pushes.

- They use your own git and its login, over https, without submodules.
  `./SPACE/.xo/state.json` remembers what was installed.
- `update` is refused when the remote is ahead or the space changed since you
  installed it: run `xo sync`. A ref its remote does not have is refused too,
  so nobody else's install breaks.
- `sync` keeps your changes and the space's. If both changed the same
  project, it stops and changes nothing. If git cannot rebase a branch
  cleanly, xo undoes the rebase and says so.

<Callout type="info">
  xo never touches a checkout with uncommitted changes, never forces a push,
  and refuses a folder whose origin is another repository or carries a login
  (`https://USER@github.com/...`).
</Callout>
