<Lead>
  **Setup** is where you tell Space which folders to use and which agent to run.
  Start with **Workspace** and **Intelligence layer**. Come back for the other
  sections when you need them.
</Lead>

![Setup Workspace with identity, folders, and section navigation](/images/space/setup.png)

Open the **Setup** tab, or press **4**. **Refresh status** checks the
installation again. A banner tells you when a saved change needs a restart.

| Section | Use it to |
| --- | --- |
| Workspace | Check who and where this Space is; choose folders |
| Intelligence layer | Pick the agent for new chats; choose which agents' activity to collect |
| Connectors | Connect tools and accounts |
| Secrets | Add, replace or remove keys and tokens |
| Commands | Save, run and schedule commands |
| Server | Restart, update, and see technical details |

## Choose your folders

In **Workspace → Folders**:

1. **Projects folder**: each folder inside it is a project. Changing it switches
   to another workspace. It does not move your projects.
2. **Space data folder**: settings, saved secrets and activity for this
   computer. The installer normally uses `.quirq/` in your workspace.
3. Click **Save folders**, then restart. **Currently using** and **Pending
   restart** show when the saved folders differ from the running ones.

If Space runs in a container, Setup shows an installer command to run instead.
Use **Copy installer command**. Add or remove single projects in **Projects →
Manage**.

## Pick your agent

![Intelligence layer with agent selection and activity settings](/images/space/setup-runtime.png)

In **Intelligence layer**, choose **Agent for new chats** and click **Save
agent**. **In use** is the agent running now; **Restart to apply** means your
saved choice starts after a restart.

**Update activity automatically** keeps sessions and project history up to date.
Scheduled commands need it on. **Activity sources** picks **All agents** or
**Chat agent only**. Click **Save activity settings**.

Each agent card shows whether its CLI is installed and whether its activity is
collected. Seeing session files does not mean the agent is signed in.

## Save secrets

Open **Secrets**, click **Add secret**, enter an uppercase **Key** and its
**Value**, and click **Save secret**. Restart when the banner asks. Space never
shows a saved value again: you can **Replace** or **Remove** it. Secrets are
kept in the Space data folder, outside your projects.

To sign in to services and apps, use [Connectors](/docs/space/space-walk/connectors).

## Usage reporting

**Intelligence layer** shows whether usage reporting is **off**, **on**,
**pending** or **blocked**. When it is on, Space sends daily token, cost and
session summaries. These leave out prompts and file contents, but error notes
can include file names. **What leaves your machine** in Setup sums this up; the
[collection guide](/docs/space/observability/collection) has the details.

## Restart the server

![Server controls for restart, updates, and technical details](/images/space/setup-server.png)

Open **Server → Restart** and click **Restart server** or **Apply & restart**.
Leave the page open: it reloads when Space is back.

If Space runs in your terminal, as it does after the one-line install, the
button is turned off. Press `Ctrl-C` in that terminal and run
`./xo-space/install.sh` from your projects folder. If Space doesn't come
back, check its terminal or log.

## Update Space

In **Server → Updates**, click **Check for updates**. **Update now** appears
when the update can apply cleanly. Restart afterwards to run the new code.

<Callout type="info">
  Updating never discards your local edits. If your copy has changes or is on
  another branch, save or sort out that work first.
</Callout>

## Run saved commands

**Commands** saves commands you run by hand or on a schedule. Nothing runs when
you open the page. Each command's **Inbox** button shows its last 20 runs, and
scheduled commands also appear in **Inbox → Jobs**. See
[Commands & schedules](/docs/space/space-walk/commands).

## Technical details

**Server → Technical details** shows where Space keeps its files and what it is
tracking. Project records travel with each project in its `.xo/` folder;
everything else stays in the Space data folder. See the
[storage map](/docs/space/observability/storage).
