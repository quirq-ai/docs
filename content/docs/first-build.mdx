## 1. Get the repo

On Linux, `qq fetch` clones a repo and runs `qq sync` in it, which downloads
the repo's pinned toolchains and checks each against its digest:

```sh
mkdir -p ~/qq-try && cd ~/qq-try
qq fetch https://github.com/quirq-ai/innernet
cd innernet
```

On a Mac, `qq fetch` clones the repo and then stops at the toolchains, which
are published for Linux only. Carry on in the clone, and see [Install qq: on a
Mac](/docs/install#on-a-mac) for the toolchain.

## 2. See what it builds

A repo is a list of **targets**. Each target has a **kind**, such as
`node-app` or `pytest`, which tells qq how to build and test it. Ask
`qqsync` rather than reading `infra/repo.toml` yourself:

```sh
qqsync show
```

It prints the manifest as JSON. For innernet there is one target, `app`, of
kind `node-app`, built with Node `24.21.0`, and the repo pins qq `0.1.0`.

## 3. Build and test it

```sh
qq test
```

`qq test` builds every target, then tests it. Each step prints one line:

```text
PASS app fetch:toolchain-check (0.1s)
PASS app fetch:install (1.5s)
PASS app build:build (13.9s)
PASS app test:typecheck (1.5s)
```

Read each line as *result, target, step*. `fetch` steps check the toolchain
and install dependencies, `build` builds, and `test` runs the checks. A
`FAIL` line names the log to open. `qq build` does the same without the
test steps.

## 4. Read the results

Everything a run produces lands in `.qq/out`:

| Path | What is in it |
|---|---|
| `.qq/out/results.json` | every step and its result, for scripts and agents |
| `.qq/out/logs/` | one log per step, such as `app.build.build.log` |
| `.qq/out/junit/` | JUnit XML, the same format CI stores |

## 5. Run it

`qq run` runs any command from the repo root with the repo's pinned
toolchains first on `PATH`:

```sh
qq run "pnpm start"
```

innernet is now at **http://127.0.0.1:3470**. **Ctrl-C** stops it. If the
repo was not synced, qq says so (`qq: not synced here: node; using PATH for
them. Run qq sync`) and uses the tools on your `PATH`.

The page says **No index yet**. That is expected: innernet searches your own
folders, and you have not indexed any. To see it with sample data, build its
demo and start it again:

```sh
INNERNET_DEMO=1 qq test
qq run "pnpm start"
```
