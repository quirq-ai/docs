## How it works

- **Transport.** Each toolchain is an OCI artifact at
  `ghcr.io/quirq-ai/toolchains/<name>`, addressed by digest: one tarball
  layer that `qq sync` unpacks without a container runtime.
- **Staging.** A spec change that lands on `main` is built in CI and pushed
  with a `staging-…` tag.
- **Promotion.** A reviewed pull request moves the staged digest into
  [`promoted.toml`](https://github.com/quirq-ai/toolchains/blob/main/promoted.toml).
- **Rolling.** The toolchain roller in [rollers](/docs/qq/rollers) opens
  pin updates in product repos. A new repo gets its pins from
  `qqsync init --promoted` ([sync](/docs/qq/sync#start-a-new-repo)).

## Add or move a toolchain

1. **Edit the spec,** `toolchains/<name>/toolchain.toml` (version, source,
   sha256), and `build.sh`. The `build` check builds it, smoke-tests it, and
   builds its consumers: product repos at a pinned commit.
2. **Land it.** `build` on `main` stages it and prints a ready-made record
   in the run summary. A staged digest is promotable only if that run's
   `consumers` job is green.
3. **Promote it** in its own pull request, which may change only
   `promoted.toml` and `README.md`:

   ```sh
   # rewrite promoted.toml in its canonical form; hand edits are refused
   python tools/qqtc.py promote <name> --record staged.json
   ```

4. **The gate checks it.** `promotion-gate` pulls the digest, checks that a
   staging build of a `main` commit produced exactly those bytes, and
   re-runs the smoke tests and consumer builds, using `main`'s tools. A
   reviewer approves, and it merges through the merge queue.
5. **The roller** opens pin updates in product repos.

To rebuild the same release, bump `revision`. For a new release, change
`version`, the source and its sha256, and reset `revision` to 1.

## Rules

- Reference toolchains only by digest, never by tag.
- Never promote a digest CI did not build from this repo.
- Change the gate itself (`.github/`, `tools/`, `toolchains/`) in its own
  pull request; suraj's code-owner review is required there.

<Accordions>
  <Accordion title="Limits of the gate, and new packages">
    Anyone with write access can push a branch whose workflow posts a green
    `promotion-gate` check, so the roller re-verifies each pin rather than
    trusting `promoted.toml` alone. A new toolchain package on GHCR starts
    private and must be made public by an org admin before `qq sync` and CI
    can pull it.
  </Accordion>
</Accordions>
