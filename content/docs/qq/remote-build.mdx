<Lead>
  The [remote-build repo](https://github.com/quirq-ai/remote-build) defines
  where a build step (an action) runs and how its result is reused. One
  executor interface runs an action on a chosen backend, and an action cache
  skips work already done.
</Lead>

<Callout type="info">
  **Today:** the executor (backends `local` and `github`) and the local
  action cache are merged. Nothing outside this repo calls it yet: `qq
  build`, `qq test` and `qqrecipes execute` run actions on the machine they
  run on. A shared cache is planned for v1; remote execution on Buildbarn
  with autoscaled workers for v2.
</Callout>

## How it works

- **An action** is a [recipes](/docs/qq/recipes) `Action`: a command, an
  input root digest, environment, outputs and platform. Its digest is its
  key. A request (`qq-exec-request/1`) adds the input files and, for remote
  backends, the git commit to fetch them from. v0 needs no gRPC.
- **An executor** runs one request and returns the exit code and the digest
  of every output. A non-zero exit code is a result, not an error.
- **Inputs are checked first.** A file that does not match the input root
  digest, or the wrong platform, is a typed error, never a silent run.
- **Backends are modules** (`qqrbe.backends.<backend>`), so a new backend is
  one new module.

| Backend | Runs the action |
|---|---|
| `local` | here, through recipes' runner |
| `github` | on a GitHub Actions runner, through the `execute` workflow |

The `github` backend needs a token with `actions: write` (`QQ_GITHUB_TOKEN`
or `GITHUB_TOKEN`).

## The action cache

`exec` and `selftest` look the action digest up in `<repo>/.qq/cache` first.
A hit restores the outputs and prints `cache: hit`; a successful miss is
stored. Actions marked `cacheable = false`, or run on a toolchain from
`PATH`, always run (`cache: uncacheable`).

With `--fallback local`, an action the backend cannot run runs locally
instead, with a `FALLBACK` line, and is counted in `.qq/cache/stats.json`.
Wrong inputs, a wrong platform or a bad request never fall back.

## Commands

```sh
qqrbe backends                                     # list backends
qqrbe selftest --backend local                     # run a small deterministic action
qqrbe exec --request req.json --backend github     # run a qq-exec-request/1
qqrbe compare local.json github.json               # same output digests?
qqrbe selftest --backend github --fallback local   # fall back if GitHub cannot run it
qqrbe stats                                        # cache hits, misses, fallbacks
```

`exec` and `selftest` exit 0 when the action passed, 1 when it did not, and
2 when the executor could not run it.
