<Lead>
  The monitoring dashboard says what changed across the quirq-ai org and what
  state everything is in. It reads the state the other qq repos already
  publish and links every value to the file or GitHub page it came from.
  suraj's Vercel project serves it at
  [monitoring.quirq.dev](https://monitoring.quirq.dev/).
</Lead>

<Callout type="info">
  **Today:** it is read-only. It never merges, approves, comments or moves a
  ref. Search, history charts, push alerts and a GitHub App in place of the
  token are v1, not started. Anything that writes (filing alerts, landing,
  releasing a hold) is v2 and waits for its own decision. The dev and stable
  channels show "nothing promoted yet" until release promotes to them.
</Callout>

## The pages

| Page | The question it answers |
|---|---|
| **Today** (`/`) | What needs a look, and what changed in the last 24 hours (or 7 days)? |
| **Waiting on you** (`/waiting`) | Which reviews, held canaries and `qq-failure` issues wait on me? |
| **Board** (`/board`) | What state is each repo in? Repos that need a look come first. |
| **Release** (`/release`) | Where is each product in release: lkgr, channels, the last 14 canary days? |
| **Health** (`/health`) | Is the dashboard's data current? Did each scheduled writer run on time? |
| **Repo** (`/repos/<name>`) | Everything about one repo |
| **Snapshot** (`/api/snapshot`) | The same state as JSON (`qq-monitoring-snapshot/1`), for agents. |

Every tile shows a state word, the detail and its source.
**Missing is never green:** a source that could not be read shows `unknown`
with the reason. `stale` means "look", not "broken": GitHub delays and drops
scheduled runs on quiet repos.

## Where the data comes from

Only public data, from the repos that own it.

| Source | What it gives |
|---|---|
| release `release-state` branch | lkgr, channels, canary runs, holds, daily reports |
| gardener `tree-status` branch | whether each tree is open or closed |
| test-pipelines `results` branch | the scorecard and failure records |
| perf `perf-data` branch | performance metrics |
| infra-config `config/repos.toml`, `config/channels.toml` | the products, channel order and cadence |
| gate `settings/github.toml` | every repo behind the gate |
| GitHub API (with a token) | PRs and reviews, check runs, deployments, writer runs, issues, the org repo list |

State branches can lag up to 5 minutes.

Two known gaps: the gardener `ledger` branch does not exist yet, so its tile
reads `unknown: ledger not started`. The one failure record on `results`
today is a planted demo; it is labelled and never counted.

## Repos it covers
