## How it works

- **Policy comes only from infra-config,** at the commit pinned in
  `pins.toml`. Manifests are read only through [sync](/docs/qq/sync).
- **Every blocking builder is a required check,** named after the builder:
  `xo-space-presubmit`, `innernet-presubmit`, `website-presubmit`.
- **Each check runs twice:** on the pull request and on the merge result in
  the queue.
- **No repo lands ungated.**
- **Only `success` passes.** Missing, running, skipped and neutral checks are
  refusals.

```sh
# the checks a repo must pass
qqgate required --config ../infra-config --repo xo-space
# the ruleset it should have
qqgate rule --config ../infra-config --repo xo-space
# pass or refuse one commit
qqgate verdict --config ../infra-config --repo xo-space --sha <commit>
```

Exit 0 is pass, 1 refused, 2 the gate could not decide, 3 the repo is not in
`repos.toml`.

## Rulesets

`settings/github.toml` holds the rulesets for all 16 repos. "Release refs"
is `qq-release-refs-branches` and `-tags`.

| Ruleset | Does |
|---|---|
| `qq-main` | `main` lands only through the merge queue with its checks |
| release refs | only the release App writes `lkgr` and channels |
| `qq-reserved-tags` | no tag named `main` or like a state branch |
| `qq-state-branches` | state branches cannot be deleted or rewritten |
| `qq-release-state` | in release: only the release App writes `release-state` |
| `qq-release-tags` | no tags in qq yet |

**Approvals.** The 13 infra repos need no approval: green checks land them.
Product repos (xo-space, innernet, website) need one, never from the author.
toolchains' build and promotion paths also need suraj's code-owner review.

**Auto-merge** puts a pull request in the queue; it skips no check or review.
It is on in every repo except xo-space.

## How an owner applies settings

An agent cannot apply them. An org owner runs `scripts/apply.sh` from the gate commit they are given, with `gh`
logged in and no exported token. It shows a dry run, asks you to type `yes`,
and writes only what you saw. Re-running is safe; it never
deletes a ruleset. The steps are in
[docs/apply-settings.md](https://github.com/quirq-ai/gate/blob/main/docs/apply-settings.md).
